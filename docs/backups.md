# Бэкапы базы данных

Автоматический ежедневный бэкап Supabase через GitHub Actions
([.github/workflows/backup-db.yml](../.github/workflows/backup-db.yml)).
Бесплатно, без сервера и без включённого ПК.

Что происходит каждый день в 03:00 UTC:
1. GitHub подключается к базе и делает дамп (`pg_dump`, схемы `public`, `auth`, `storage`).
2. Дамп шифруется AES-256 твоим паролем.
3. Зашифрованный файл сохраняется как **приватный артефакт** (90 дней).

Побочный плюс: этот дамп ежедневно «будит» базу — работает и как keep-alive.

---

## Настройка (один раз)

Нужно добавить **два секрета** в GitHub:
**Settings → Secrets and variables → Actions → New repository secret**

### 1. `SUPABASE_DB_URL`
Строка подключения к базе.
Supabase → **Project Settings → Database → Connection string → Session pooler**
(вкладка «Session mode»). Скопируй URI вида:

```
postgresql://postgres.xxxx:[ПАРОЛЬ]@aws-0-<регион>.pooler.supabase.com:5432/postgres
```

Подставь вместо `[ПАРОЛЬ]` пароль базы (тот, что задавал при создании проекта;
если забыл — там же можно сбросить: Database → Reset database password).

> ⚠️ Бери именно **Session pooler** (он по IPv4). «Direct connection» работает
> только по IPv6 и из GitHub Actions не подключится.

### 2. `BACKUP_PASSPHRASE`
Придумай надёжный пароль для шифрования бэкапов и **сохрани его в менеджере
паролей**. Без него расшифровать бэкап будет невозможно.

### 3. Проверить
Actions → **Backup database** → **Run workflow** (кнопка справа). Через минуту
во вкладке этого запуска внизу появится артефакт `db-backup-…`. Готово — дальше
он будет создаваться сам каждый день.

## Как восстановить (если что-то случилось)

1. Скачай нужный артефакт: Actions → Backup database → выбери запуск → Artifacts.
2. Распакуй zip — внутри файл `flyyoga-….dump.gpg`.
3. Расшифруй (нужен установленный GnuPG):

   ```bash
   gpg --batch --passphrase 'ТВОЙ_ПАРОЛЬ' -o flyyoga.dump -d flyyoga-….dump.gpg
   ```

4. Восстанови в базу (новый проект Supabase или локальный Postgres):

   ```bash
   pg_restore --no-owner --no-privileges --clean --if-exists \
     -d "postgresql://postgres.xxxx:[ПАРОЛЬ]@aws-0-<регион>.pooler.supabase.com:5432/postgres" \
     flyyoga.dump
   ```

Главное здесь — схема `public` (клиенты, абонементы, заявки). Восстановление
`auth` (аккаунты) в новый проект Supabase может потребовать ручной доработки —
но данные из дампа никуда не денутся, и это всегда можно сделать спокойно.

## Заметки
- Хранение: последние ~90 ежедневных копий (лимит артефактов на free-плане).
  Если захочешь бессрочное хранение — заведём отдельный приватный репозиторий
  под бэкапы или зальём в облако.
- Файлы из Storage (аватары) в дампе не лежат — там только метаданные. Сами
  картинки при желании бэкапятся отдельно; для клиентских данных это не критично.
